# Generated Project Checklist

- [ ] Requirements and assumptions are traceable.
- [ ] Each requirement has a source reference, acceptance criterion, and implementation/test or an explicit gap.
- [ ] The selected project context, mapping specification, and unresolved decisions are recorded.
- [ ] Existing-project changes have an impact assessment and baseline results; unrelated work and contracts are preserved.
- [ ] API-led architecture and API ownership are documented.
- [ ] RAML and examples validate.
- [ ] Maven project builds reproducibly.
- [ ] Secure properties and TLS are configured.
- [ ] No credentials or private values are source-controlled.
- [ ] DataWeave mappings cover null, date, and boundary cases.
- [ ] Entry flows delegate meaningful processing; flow references resolve and refactoring preserves event state, errors, transactions, concurrency, and side-effect order.
- [ ] MUnit success, negative, timeout, retry, and replay cases exist.
- [ ] MUnit commands, test counts, reports, and passed/failed/blocked results are recorded; skipped tests are not reported as passes.
- [ ] Streaming, pagination, batching, pooling, caching, and retry limits are suitable.
- [ ] CI build, test, security, and deployment gates exist.
- [ ] Health, metrics, logs, alerts, rollback, and replay are documented.
